# anuenue — audit delta for v1.4.0 (cyrius 6.7.9 + darshana 1.3.0)

**Scope**: everything the v1.4.0 cut touched — the toolchain move (cyrius 6.6.2 →
6.7.9, `lib/` re-vendored), the dependency moves (darshana 1.1.1 → 1.3.0 with its
`path` dropped, sakshi 2.5.1 → 2.5.8), and the one source change they carried:
`src/animate.cyr`'s exit-signal fd moving from a hand-rolled copy onto darshana.
Input was the darshana consumer survey (2026-10-12), whose items were "confirmed
by reading the source; not yet reproduced by running it". Recorded as a delta vs
the [2026-08-26 sweep](2026-08-26-audit.md), per the audit cadence in
[`roadmap.md`](../development/roadmap.md#ongoing-cadence--not-milestones).

**Result: 4 findings — 1 LOW, 3 INFO — all fixed in-cut. Zero HIGH+ open.**
G-01 and G-02 were reproduced by running the v1.3.6 code; G-03 and G-04 are
properties of it, confirmed by reading and (G-04) by re-measuring `sleep_ms`.

---

## Findings

### G-01 — a failed signalfd open unblocked signals it never blocked · LOW

`_open_exit_signalfd` blocked `TTY_SIGMASK_EXIT` with `oldset = 0`, and on a
failed `signalfd(2)` rolled back with `SIG_UNBLOCK` of the whole mask. A signal
that was **already** blocked when animation started came back unblocked.

Reproduced on v1.3.6: a probe blocks SIGHUP, calls `_open_exit_signalfd` under
`prlimit --nofile=3` (so `signalfd(2)` is the first call to want fd 3, and
fails), then reads the mask — `fd=-1 hup_blocked=0`.

Who blocks it beforehand: a parent that spawns anuenue while holding a signalfd
of its own — the hazard darshana's 1.1.4 notes call "the block is inherited by
children". Consequence: a signal the parent meant to hold becomes deliverable in
anuenue with its default action, which for HUP/INT/TERM terminates it. LOW
because it needs both a failing `signalfd(2)` (descriptor or memory exhaustion)
and a parent that blocked one of the three.

darshana fixed exactly this in its own `tty_open_signalfd` at 1.0.2 (roll back
`sigmask & ~prev` only). **Fix**: call it. Gate: `scripts/signal-check.sh`
gate 1, `preblocked` row — `exit_bits_blocked=1` under `--nofile=3`.

### G-02 — the exit signalfd was not close-on-exec · INFO

The fd was opened with `ANUENUE_SFD_NONBLOCK` alone. Reproduced on v1.3.6:
`cloexec=0`. anuenue never execs, so this was latent — nothing could inherit it.
**Fix**: darshana's open passes `SFD_CLOEXEC`; non-blocking comes from the
stdlib's `fd_set_nonblocking` (cyrius 6.6.8+), the route darshana documents.
Gates: `signal-check.sh` gate 2 (`cloexec=1`, `nonblock=1`) and the v1.4.0 unit
group (both flags read back with `fcntl`).

### G-03 — the signalfd was never closed and the mask never restored · INFO

The [2026-05-22 audit](2026-05-22-audit.md)'s INFO 8 + 9, accepted then because
"the process exits before the mask matters". Still true — but darshana's API
pairs every open with `tty_close_signalfd`, and the pairing is what lets the
mask come back as it was found. **Fix**: `_close_exit_signalfd`, the LAST step
of every exit path out of the frame loop (darshana's teardown order, its ADR
0002 as amended at 1.1.4), unblocking only what the open added.

**The fix introduced a hazard, caught and closed in-cut.** The unblock delivers
any signal still pending with its default action. The frame loop reads one
signal per probe, so with SIGINT and SIGTERM both pending the close turned the
documented "SIGINT → exit 0" into death by SIGTERM: **exit 143**, measured by
mutation (3 of 3 runs). `_close_exit_signalfd` drains the fd first (bounded at
`ANUENUE_SIG_DRAIN_MAX = 8`), which keeps the v1.3.6 outcome — exit 0, 3 of 3
runs on both v1.3.6 and v1.4.0. Gates: `signal-check.sh` gate 5, and the unit
group, which sends itself SIGINT + SIGTERM before the close: without the drain
the test process is killed.

### G-04 — a diagnostic stated a cause that is no longer true · INFO

`-i` above one hour logged `--interval clamped; sleep_ms truncates to a 32-bit
int above this`. cyrius 6.6.20 made `sleep_ms` clamp (negative → 0, above
INT_MAX → INT_MAX); re-measured on 6.7.9, every value above INT_MAX blocks and
-1 returns at once. The clamp stays — it is user-visible behaviour — but the
record now says only what happened: `--interval clamped to one hour per frame`.
stderr only, only at `--log-level=warn` or finer; `signal-check.sh` still
matches `interval clamped`. [Architecture 005](../architecture/005-timing-primitives-truncate.md)
carries the re-measurement.

## Also checked

- **One new branch is unproven.** If `fd_set_nonblocking` fails, the open closes
  the fd and unblocks what it added. `F_GETFL` / `F_SETFL` on a signalfd the
  process just opened has no failure a test can provoke, so no gate reaches it —
  recorded rather than implied, as the v1.3.x audits did for D-01 and E-01.

- **Capability surface.** Filter, passthrough and positional-text paths are
  unchanged. Animation adds `fcntl(72)` twice (F_GETFL / F_SETFL, inside
  `fd_set_nonblocking`) and `close(3)` at teardown, on top of `rt_sigprocmask`,
  `signalfd4`, `poll` (`sleep_ms`) and `clock_gettime`. From the code: there is
  no `strace` on the audit host, so this is read, not traced. No exec, no
  network, no file open beyond the startup `/proc/self/cmdline`.
- **The 6.7-series language changes.** None reaches anuenue's own source:
  no identifier spelled `const` / `true` / `false` / `do` / `dyn` / `trait` /
  `loop`, no `!` other than `!=`, no compound assignment, no typed narrow
  pointer, no unary `-` / `~` on a constant (the source writes `(0 - N)` by
  convention). The two `~` this cut adds are on variables. The toolchain move
  compiled with zero errors and zero warnings for x86_64, and the outputs are
  byte-identical to v1.3.6 across 276 stdout + exit-code comparisons.
- **The `path` dependency.** `[deps.darshana]` carried `path = "../darshana"`,
  and under cyrius 6.6.2 that made `cyrius deps` vendor the sibling's working
  tree: the never-committed 2026-09-26 `lib/` held darshana 1.1.2, cmdit 1.2.5
  and agnostik 1.6.4 under tags 1.1.1, 1.2.4 and 1.6.0. From cyrius 6.7.6 a
  `path` beside `git` + `tag` is a `CYRIUS_LOCAL` dev override and the tag
  builds by default. darshana's entry is gone; cmdit, sakshi and agnostik keep
  theirs, which no longer affects a default build.
- **Escape-table re-measurement** (survey item). Kept — deleting it measured
  −15% on truecolor but +33% / +42% on 256 / 16. Numbers in
  [`benchmarks.md`](../benchmarks.md#v140--cyrius-679--darshana-130).

## Upstream, not anuenue's to fix

- **cyrius 6.7.9 `distlib` records a named dep's leaf as the bundle's own.**
  `dist/anuenue.deps` is now one leaf, `boxed`, though `src/hsv.cyr` calls
  nothing. `cyrius distlib -v` says why: `boxed recorded for 'tagged_new'`.
  `tagged_new` is called by agnostik's bundle and defined in `lib/boxed.cyr`;
  agnostik's sidecar lists `tagged`, which includes `boxed`, so the verify
  does not see `boxed` as brought by the named dep and credits it to anuenue.
  Harmless for consumers of `dist/anuenue.cyr` (one extra include), but wrong.
- **agnostik 1.6.0 calls `syscall(318, …)` raw** (`getrandom` on x86_64), which
  the aarch64 build warns about. Pre-existing (6.6.2 warns too), aarch64 is not
  an anuenue CI target, and agnostik ≥ 1.6.3 spells it differently. Not bumped:
  the toolchain move does not require it.

## Declined, from darshana 1.2.0 / 1.3.0's additions

- **`TTY_SIGMASK_PIPE`.** It exists so a TUI is not killed by SIGPIPE mid-
  teardown with the terminal raw. anuenue has no terminal state at risk when
  stdout is a pipe — its escapes went down the pipe — and blocking SIGPIPE would
  add a signalfd to the *filter* path, whose capability surface is
  read/write/brk, and turn the default-disposition `anuenue | head -1` exit
  from 141 to 0. Nobody asked for that change.
- **`tty_sanitize_buf`.** anuenue's contract is byte preservation (the
  robustness gate checks all 256 byte values pass through); neutralising control
  bytes in stdin would break it.
- **`tty_winsize_or`.** The one place it would matter is a block taller than the
  terminal, which is the v1.3.3 sweep's open surface #3 — its own slot, not a
  side effect of a dependency bump.
