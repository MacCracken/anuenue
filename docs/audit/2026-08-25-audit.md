# anuenue — P(-1) audit, 2026-08-25 (v1.2.2)

**Scope**: full source sweep — correctness, hardening, security, refactor,
optimization, documentation. Run against the v1.2.1 tree, fixes shipped in
v1.2.2.

**Result**: **9 findings** — 2 MEDIUM, 5 LOW, 2 INFO. All fixed in-cut. **Zero
HIGH+ open.** Every fix carries a regression test that fails if the fix is
reverted.

The previous audit ([2026-05-22](2026-05-22-audit.md), v0.8.0/M8) found one HIGH
— a heap overflow on long-cluster animation input. That fix still holds; this
audit re-verified it and extended the surrounding coverage.

---

## Method

Four passes, in this order, because each one fed the next:

1. **Cleanliness** — `cyrius build` / `lint` / `audit` / `test` / `fuzz`. This is
   what surfaced A-07 and A-08.
2. **Adversarial execution, not reading.** Byte-stream corpora (malformed UTF-8,
   chunk-boundary splits, all 256 byte values) and argv corpora (every integer
   flag at both i64 extremes) run against the real binary. A-01 was found by
   reading; **A-02, A-03, A-04 and A-05 were found by running**, and would not
   have been found by reading — each looks correct in isolation.
3. **Capability re-verification** — syscall surface, allocation sites, stack
   buffer sizes, injection sinks.
4. **Regression capture** — everything the sweep exercised that the permanent
   suite did not is now `scripts/robustness-check.sh`, wired into CI.

A note on what the audit is *for*: three of these nine findings are the same
defect wearing different clothes — **a silent fallback where an error belonged**
(A-03, A-04, A-05). A-09 is the compound interest on one of them. That pattern,
not any individual bug, is the finding worth remembering.

## Findings

### A-01 — `_cp_ext_init` writes 42 words through an unchecked allocation · MEDIUM

`src/filter.cyr`. The extending-codepoint range table is built lazily:

```
_CP_EXT_TABLE = alloc(n * 16);
var p = _CP_EXT_TABLE;
store64(p +   0, 0x0300);   store64(p +   8, 0x036F);
...                                                     # 42 stores in total
```

`lib/alloc.cyr` returns **0** on OOM or an out-of-range size — it does not
abort. With `p == 0` the function writes to absolute addresses `0x000`–`0x148`.

Two things made it worse than a crash:

- **It is inconsistent, not deliberate.** `_phase_esc_init`, 200 lines above in
  the same file, checks its `alloc` and returns `-1`. This call site simply
  never got the same treatment.
- **The failure was unobservable.** `_cp_ext_init` returned 0 (success)
  unconditionally, and its only caller — `cp_is_extending` — invoked it as
  `if (_CP_EXT_TABLE == 0) { _cp_ext_init(); }`, discarding the result. Had the
  null write not faulted, the binary search would have run against a null table.

This is the exact class cmdit's own 1.2.4 audit hardened ("stdlib `alloc`
returns 0 on failure and every call site ignored it"), reaching anuenue through
a different door.

**Severity MEDIUM, not HIGH**: the size is a compile-time constant (336 bytes),
so no input can drive the allocation to fail. Reaching it requires genuine heap
exhaustion. But the failure mode is a null-pointer write, not a bad render.

**Fix** — check the allocation, return `-1`, and make the caller honour it.
`cp_is_extending` now answers "not extending" when the table is unavailable.
That is the right degradation for this program: every caller treats 0 as "starts
a new cluster", so the rainbow keeps advancing and **output stays byte-correct**
— only cluster grouping degrades. Byte preservation is the contract; cluster
grouping is the nicety.

**Regression**: `tests/anuenue.tcyr` — "A-01" group. Asserts init succeeds and
reports success, that re-entry does not reallocate, and the four range
boundaries the binary search must get right.

### A-02 — a long `--duration` makes the animation exit *immediately* · MEDIUM

`src/animate.cyr`:

```
deadline_ns = start_ns + duration_secs * 1000000000;
```

`duration_secs * 1000000000` overflows i64 above ~9.22e9 seconds. At `i64::MAX`
the product is congruent to **exactly −1e9**, so:

```
deadline_ns = start_ns - 1000000000     # one second in the PAST
```

and the first deadline check ends the loop. Measured:
`anuenue -a -d 9223372036854775807` exited **after a single frame** — the
precise inverse of the request.

The value is user-supplied argv. No memory-safety consequence; the deadline is
only compared, never used as an index.

**This was an accepted INFO finding, and the acceptance was wrong.** The
2026-05-22 audit recorded it as a "large `-d` graceful-exit boundary at ~292
years" and `state.md` carried that description forward. Re-measuring shows the
behaviour is the *inverse*: not a graceful exit at a distant boundary, but an
immediate one-frame exit at any duration above ~9.22e9 seconds. Nobody
introduced a regression — the original characterisation was never measured.

The cadence lesson, recorded in `state.md`: **an accepted INFO finding is a
hypothesis about behaviour, not a measurement of it.** The two remaining INFO
items from 2026-05-22 (signalfd lifecycle on animation exit, signal mask not
restored after completion) have *not* been re-measured and are the first
candidates for the next sweep.

**Fix** — clamp to `ANUENUE_MAX_DURATION_S = 4e9` seconds (~127 years) before
converting. Clamping rather than rejecting: a duration past the end of the
terminal session means "keep going", and clamping honours that where overflowing
inverted it.

The bound is deliberately **well below** the arithmetic maximum (~9.22e9 s). At
the tightest valid clamp the constant would silently depend on which clock the
stdlib returns: `clock_now_ns()` is `CLOCK_MONOTONIC` today (boot-relative,
~8.6e13 ns on a day-old host, `uptime_ms * 1e6` on agnos), but an epoch-relative
reading is ~1.79e18 ns. 4e18 + 1.79e18 = 5.79e18, comfortably inside i64::MAX
under either.

**Regression**: unit group "A-02" pins the clamp's arithmetic — including an
assertion that `i64::MAX * 1e9` really does wrap negative, so nobody
"simplifies" the clamp away. `robustness-check.sh` asserts the process still
runs at 3 s under a huge `-d`, and still exits on time under `-d 1`.

### A-03 — a negative `--duration` silently means "run forever" · LOW

`if (duration_secs > 0)` left `deadline_ns` at 0 for negative input — and 0 is
the *documented sentinel* for "run until SIGINT". So `-d -1` inherited
"forever", an undocumented behaviour reachable only by accident.

**Fix** — reject negative `--duration` as a usage error (exit 2). `0` remains the
explicit way to say "until SIGINT". Validated unconditionally rather than only
under `-a`, so the error does not depend on flag order.

### A-04 — an unrecognised `--color` value silently means `auto` · LOW

`_color_override_from_str` returned `ANUENUE_COLOR_OVERRIDE_AUTO` for every
string it did not recognise. `--color=trucolor` therefore ran full colour
detection while the user believed they had forced truecolor, exit code 0,
nothing on stderr.

The original comment defended this as "a typo doesn't silently force a colour
mode the user didn't intend" — but **AUTO is a mode**. The fallback did not avoid
a silent wrong outcome, it chose a different one.

v1.2.1 had already made exactly this call the other way for `--log-level`
("the failure mode of a silent default here is a user who asked for output, got
none, and concludes the tool is broken"). The two flags now agree.

**Fix** — new `ANUENUE_COLOR_OVERRIDE_BAD` sentinel; `main.cyr` turns it into a
usage error listing the accepted values. A null or empty string still means AUTO
— that is "flag absent", not "bad value". The five override constants were
converted from initialized globals to an enum in the same change, per the
CLAUDE.md convention.

### A-05 — animation drops input past its caps, in silence · LOW

Animation slurps at most `ANUENUE_ANIMATE_INPUT_MAX` (64 KB) and tags at most
`ANUENUE_ANIMATE_CLUSTER_MAX` (8 192) clusters. The caps are deliberate (M4:
"render what fit; don't OOM") — but the consequence was understated. `_pretag_clusters`
writes its sentinel at **the byte offset where it stopped**, so text past the cap
is not merely rendered in one colour: it is **never rendered at all**.

Measured: a 200 001-byte input animated as exactly 8 192 characters per frame,
with nothing said on any file descriptor.

**Fix** — warn on both caps via sakshi (`SK_WARN`), so `-v` / `--log-level=warn`
explains the missing text. The caps themselves are unchanged; this is a
discoverability fix, not a behaviour change. Verified that the warning does not
reach a default-verbosity run.

### A-06 — animation's failure paths returned a bare `1` · LOW

v1.2.1 routed the filter and passthrough failures through `anuenue_fail` (so
they carry an agnostik kind and a message) but missed `anuenue_animate`: three
allocation failures and the stdin read error still returned `1` with **no output
on any descriptor**.

**Fix** — routed through `anuenue_fail`. Exit codes unchanged. The animation path
now also accumulates `ANUENUE_BYTES_IN`, which it previously did not, so `-v`
reports byte counts for `-a` runs too.

### A-07 — four files failed `cyrius fmt`, and the formatter's fix was worse · INFO

`cyrius audit` reported `animate.cyr`, `hsv.cyr`, `main.cyr` and `filter.cyr`
needing reformatting. Applying the formatter was mostly benign — `animate.cyr`
and `main.cyr` got *shallower* (max indent 38→16 and 44→24 columns).

`hsv.cyr` was the exception. `hsv_rainbow`'s six-sector colour table is a
`} else { if (...) {` chain, which the formatter indents one level deeper per
arm, cascading sector 5 to **24 columns** and destroying the parallel alignment
that is the whole point of a lookup table.

**Fix** — restructured the six arms as a flat run of early returns. Reads as the
table it is, is naturally format-stable, and drops the trailing `} } } } }`
pile. **Emitted bytes are unchanged** — all six golden fixtures are byte-identical
across the refactor, and `hsv_rainbow` still benches at 8 ns.

Worth recording, since `hsv.cyr` is the distlib module consumers include: this
was a formatting-driven refactor of the one file that ships as a library, and it
is semantically inert.

### A-08 — eight public functions had no docstring · INFO

`cyrius audit` docs gate: `anuenue_color_reason_name`, `anuenue_color_mode_name`,
`cp_is_extending`, `main` (×2), `anuenue_span_exit`, `anuenue_log_kv_str`,
`anuenue_log_kv_int`. Several were covered by a shared block comment above a
group, which the checker does not credit — and is right not to, since a reader
arriving at the second function in a group sees nothing.

**Fix** — per-function docstrings stating the return contract. The docs gate is
now clean.

### A-09 — `--color=mono` was documented for four months and never implemented · LOW

Surfaced **by fixing A-04**, not by the sweep. With unknown values rejected,
`docs/examples/06-no-color.sh` started failing — it runs `--color=mono`, and its
header lists "`--color=none` / `--color=mono`" as the explicit override. The
parser had no branch for `mono`. It fell through to AUTO, so the example ran
colour detection while claiming to demonstrate forced mono, **and exited 0**.

This is the strongest argument in the whole audit for A-04's fix. The silent
fallback did not just swallow user typos — **it hid our own broken documentation
from our own example suite**, which CI runs on every push.

**Fix** — implemented `mono` as a synonym for `none`. The documentation was
right; the code was wrong. Help text and the A-04 error message now list all
nine accepted values (`auto`, `24bit`, `truecolor`, `256`, `16`, `none`, `mono`,
`off`, `never`), which were previously partly undocumented in the other
direction.

Checked and found sound. Recorded so the next audit knows what was covered.

## Deferred

- **`main.cyr:178` / `filter.cyr:132` keep `} } } }` chains.** Both are genuine
  4-way dispatches at modest indent (≤24 columns) and both pass `cyrius fmt`.
  Flattening them would be churn, not clarity. Revisit only if the formatter's
  rules change again.
- **`-p -9223372036854775808` is rejected while `i64::MAX` is accepted.** cmdit's
  integer parser refuses the most-negative i64 (the negate-MIN case). Rejecting
  is the safe direction, and the asymmetry is cmdit's to resolve, not anuenue's.
  Recorded so the next audit does not re-derive it.
- **Parse errors still cannot be logged.** Observability is configured from
  parsed flags, so a `cmdit` failure precedes the level being known. Documented
  in [ADR 0004](../adr/0004-stderr-only-observability.md); a pre-parse argv scan
  would duplicate cmdit's tokenizer.
