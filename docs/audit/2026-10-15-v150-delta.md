# anuenue — audit delta for v1.5.0 (no-colour spans)

**Scope**: v1.4.5 → v1.5.0. The minor-cut P(-1) sweep, aimed at the one new
surface: a second input grammar (the no-colour markers,
[ADR 0006](../adr/0006-no-colour-spans.md)) parsed on every route, and the
span state each route gained. The surfaces:

1. the marker recogniser and its carry across the 4096-byte read;
2. what each route writes at a span's edges, and at the end of the input;
3. animation's row count over escape sequences that now reach the terminal
   intact;
4. the line-buffer geometry proof ([architecture 001](../architecture/001-buffer-geometry.md))
   against the new write paths.

An independent code review of the `src/` diff ran alongside. Recorded as a
delta vs the [v1.4.x delta](2026-10-14-v14x-delta.md), per the audit cadence.

**Result: 12 findings — 1 HIGH, 2 MEDIUM, 5 LOW, 4 INFO. Ten fixed before
release, two recorded (V-11 pinned to v1.5.2, V-12 terminal-dependent). None
reached a release: every one was in v1.5.0's own new code or gates, found by
writing the gates (V-01 to V-05) or by the independent review (V-06 to V-10,
and the cases recorded in V-11 and V-12). Zero HIGH+ open.**

---

## Findings

Every finding below was found and fixed before v1.5.0 shipped. None reached a
release: they are recorded because each changed the design or a gate.

### V-01 — an unclosed span left the producer's colour set after anuenue exited · LOW

`off` with no `on` runs to the end of the input (ADR 0006, decision 4). The
filter wrote its usual end-of-input reset only when the last line was still
unflushed. So `ab<off>ESC[31mcd\n` ended in `ESC[31mcd\n` with no reset, and
the one-shot route, which appends the LF itself, always did. Either way the
shell prompt came up red. Without anuenue the producer's output would leave the
terminal red too, but anuenue's standing guarantee is that it returns the
terminal clean.

**Fix**: the end of the input closes an open span like an `on`, with one reset,
on the filter (EOF and the read-error path) and the one-shot route. Animation
already reset at every frame's end. ADR 0006 decision 4 now says so.
**Gate**: robustness gate 11 `EOF` (filter with and without a final LF,
one-shot). Removing either route's close fails it.

### V-02 — the row count misparsed intact escape sequences inside a span · MEDIUM

Inside a span the producer's sequences reach the terminal intact, so H-01's
physical-row count has to parse them as the terminal does. The first cut knew
CSI and OSC only, and got three things wrong:

| Input inside a span | Terminal | First cut | Effect per frame |
|---|---|---|---|
| `ESC [ 3 LF a b` — an LF inside an unfinished CSI | executes the LF (VT500: C0 controls execute in CSI) | swallowed it | climbs a row short: scrolls |
| `ESC [ 3 ESC [ 1 m` + 80 columns | the second ESC restarts: an SGR | `1m` counted as text: 82 columns | climbs a row too far |
| `ESC _ … ESC \` (APC), `ESC P … ESC \` (DCS), `ESC ( B` | the string / intermediates take no columns | counted as text | climbs too far |

A climb that falls short scrolls a copy of the block into scrollback every
frame, the H-01 failure. A climb that goes too far scrolls nothing. It draws
each frame higher, over whatever is above the block, and the PTY gate could not
see that (V-05). MEDIUM, by H-01's own reasoning: it is the animation's main
path for any span that carries more than SGR.

**Fix**: `_span_vt`, one step of the VT500 parser (xterm's) for the subset that
decides width: ESC restarts from any state; CAN / SUB abort; C0 controls execute
in ground, escape and CSI; CSI to its final byte; OSC to BEL or ST; DCS / SOS /
PM / APC strings to ST; escape intermediates; DEL ignored.
**Gates**: unit group `_span_vt` (20 transitions) and the row-count group (7
cases). PTY gate 5 gains six span cases, played into a terminal model that now
implements the same states independently. On the first cut, `span-apc`,
`span-lf-inside-csi` and `span-adjacent` fail.

### V-03 — adjacent spans shared attributes in animation · LOW

The filter writes a reset at every marker, so `off A on off B on` gets a reset
between A and B. Animation's prepare pass removes the markers, and the renderer
reset only on entering raw from ordinary text, so A and B went out as one raw
run. A's attributes, or an OSC A left unterminated, ran into B: an unterminated
title swallowed B entirely, and the row count followed.

**Fix**: the first byte of each span is flagged in the span map, and its cluster
gets `ANUENUE_CF_OPEN`. The renderer writes a reset before it, and the row count
restarts its parser there. **Gates**: robustness gate 11 `ADJACENT` (all three
routes), PTY `span-adjacent`, the marker fuzz harness's `CF_OPEN` invariant.
Dropping the renderer's reset or the count's restart fails the PTY case.

### V-04 — a reserve flush inside a span wrote a reset · INFO

ADR 0006 decision 2: nothing of anuenue's inside a span. The filter's EOF carry
loop flushed a full line buffer with its usual reset whether or not a span was
open. That needs a carried, unfinished `on` (at most 14 bytes) on a line within
32 bytes of the 32 KiB buffer's end. **Fix**: no reset there inside a span.
**Gate**: robustness gate 11 `RESERVE` builds exactly that input (32 726 span
bytes, then a carried `on` prefix at EOF) and counts two resets. The unfixed
loop writes three.

### V-05 — the PTY gate could not see a climb that goes too far · INFO (gate)

`scripts/term-model.py` reported scrolling only. A climb that is too far
scrolls nothing, so every over-climb, V-02's included, passed. It also modelled
only CSI, so it would have printed an intact OSC or APC as text and disagreed
with any correct count. **Fix**: the model records where every cursor-up aims.
Gate 5 now requires one anchor row across frames and no climb past the top,
and the model parses OSC / DCS / SOS / PM / APC as xterm does. Every existing
case still passes, and the six span cases are new.

### V-06 — empty spans overflowed the line buffer · HIGH

Found by the independent review, after my own reading of the same code had
called it INFO.
[Architecture 001](../architecture/001-buffer-geometry.md)'s invariant: every
write is followed by the reserve check, so an iteration starts with `pos ≤
LINE_BUF − 32`. The resets written at the markers had no check after them.
I first read that as a 4-byte excess at the escape budget, never reached with
the 17-byte escapes anuenue emits. That analysis took one marker at a time.
An **empty span**, `off` then `on`, writes two resets (8 bytes) and no byte,
so nothing triggers a flush, and a run of them grows `pos` without bound until
the next LF:

| Input | Route | Result |
|---|---|---|
| `a` + 4 200 × (`off` `on`) + `b` | one-shot (argv) | **SIGSEGV** |
| `a` + 5 000 × (`off` `on`) + `b` LF | filter (stdin) | a 40 KB line written from a 32 KB buffer, overwriting the read buffer: 38 raw markers reach stdout |
| … 100 000 × | filter | the phase table overwritten: `b` tinted `255;196;0`, not `255;7;0` |
| … 4 M × | filter | 32 MB written past the buffer |

HIGH: memory corruption reachable from stdin and argv, both untrusted. It
never shipped.

**Fix**: `_reset_checked`, an SGR reset followed by the reserve check, at
every marker reset: `off` on the filter and the one-shot route, `on` in
`_span_walk`, and the leave-span reset in `_render_frame`. Animation's prepare
pass never wrote resets for empty spans (V-08), so the overflow was never
reachable there. 001's write-path table lists the span paths.
**Gate**: robustness gate 11 `EMPTY`: 100 000 empty pairs on the filter and
4 400 on the one-shot route must exit 0, leak no marker and leave `b`'s hue
alone. With the check removed, the one-shot run dies with SIGSEGV.

### V-07 — an extender after a span: animation and the filter disagreed · MEDIUM

The filter folds a combining mark straight after a span into the cluster
*before* the span (no phase step), as ADR 0006's phase pause implies: remove
the span, and `e` + U+0301 is one cluster. Animation's pre-tag gave the mark a
cluster of its own, with a phase step. So for `e<span>U+0301 b` every later
cluster of every frame was one hue behind the filter. The row count also
gave the lone mark a column. The terminal joins it to the span's last cell, so
an 80-column line counted 81, and the block climbed a row too far every frame.

**Fix**: the mark opens a cluster flagged `ANUENUE_CF_JOIN`, counted like span
text (no columns), and `ANUENUE_CF_CONT` when there is a cluster before the
span to continue. CONT is drawn at that cluster's phase and takes no step.
After an LF, H-05's rule holds as it does without a span (V-11). **Gates**:
robustness gate 11 `ROUTES` (the filter, the one-shot route and animation frame
0 agree on hues and bytes over ten span-edge inputs), PTY `span-mark-after`,
and unit group V-07. Never setting CONT fails `ROUTES`; counting JOIN as
columns fails the PTY case.

### V-08 — animation did not see empty spans · LOW

The prepare pass removed an empty span without a trace. The filter resets its
ZWJ and regional-indicator latches at `off`, so after `a ZWJ <empty span> b`
the `b` is a cluster of its own there. In animation it joined `a`'s, and every
later cluster was one hue behind. The same happened with a flag pair split by
an empty span. Animation also wrote no reset there.

**Fix**: the span map marks the first byte after an empty span (4). Its
cluster gets `ANUENUE_CF_OPEN` (a reset before), and the latches reset there.
**Gates**: `ROUTES` (the ZWJ and the flag cases), unit group V-08, and the
marker fuzz harness's span-map reference. Never marking an empty span fails
`ROUTES`.

### V-09 — a UTF-8 sequence ran across a span edge in animation · LOW

`a \xE4 <span>\xB8\xAD</span> x`: the filter meets the marker's ESC after the
lead byte, so the lead is a lone invalid byte and the tail is span text. The
prepare pass removes the marker, so the bytes touch, and the pre-tag decoded
`中` as one ordinary, tinted cluster: span bytes tinted, which contradicts
decision 1. **Fix**: `_seq_len_in` bounds the sequence at the span edge.
**Gates**: the marker fuzz harness (the token pool now cuts sequences, and no
span edge may fall inside a cluster), `ROUTES` (bytes compared), unit group
V-09. Removing the bound fails both.

### V-10 — after an escape intermediate, `[ ] P X ^ _` began a sequence · LOW

`_span_vt` held ESC and ESC-plus-intermediates in one state. After `ESC (`, a
`_` is a final byte in the VT500 parser, but the count entered APC state and
swallowed the rest of the span: `ESC ( _` + 100 columns counted 0 rows of
wrap where the terminal shows two. **Fix**: an escape-intermediate state of its
own. The terminal model had the same error and is fixed independently.
**Gates**: unit group V-10 and `_span_vt`'s transitions, PTY
`span-esc-intermediate`. Merging the states again fails it.

### V-11 — recorded: two phase disagreements older than v1.5.0 · INFO

Neither is new, and neither changes in this release (one change at a time).
Both are pinned to the roadmap's v1.5.2 slot:

- **An extender straight after an LF.** The filter folds it into the LF with
  no phase step. Animation (H-05, v1.4.4) gives it a cluster and a step, which
  is what UAX #29 says (GB4: break after a control). The filter is the one to
  change, and the row count's 1 column for such a mark is the other half of
  it.
- **The filter's EOF carry ignores the ZWJ and RI latches.** A ZWJ followed by
  a carried prefix (a lone ESC since v1.4.5, `ESC _` since v1.5.0) at the end
  of the input steps the phase on the filter, but not on the one-shot route.

### V-12 — recorded: terminal-dependent cases in the span row count · INFO

Both depend on the terminal, and there is no single right answer to count:

- C1 controls encoded in UTF-8 inside a span (U+009B CSI, U+009D OSC). The
  count gives them no columns but does not enter a sequence. xterm and VTE may
  execute them.
- A non-ASCII byte inside a CSI ends it and counts as text. A VT500 maps GR to
  GL, so there it would be a final byte.

A producer that writes either inside a span may see the animation climb one row
off. Pinned to the roadmap's trigger table: the trigger is a producer that does.
