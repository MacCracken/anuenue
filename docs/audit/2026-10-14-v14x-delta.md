# anuenue — audit delta for the v1.4.x arc (v1.4.4 closeout + P(-1) sweep)

**Scope**: the v1.4.x arc, v1.4.0 → v1.4.4: the dependency refresh (cmdit 1.4.0,
agnostik 1.12.0, sakshi to the stdlib), the stderr hygiene and argv echo (v1.4.2),
the escape-table word copy (v1.4.3), and this cut's own changes. The sweep's
surfaces were the ones [`roadmap.md`](../development/roadmap.md) listed for v1.4.4,
picked by the v1.3.3 method — *what has never been looked at*:

1. animation under a constrained terminal;
2. a stdin that never closes;
3. the guards recorded as unproven.

It also ran the CLAUDE.md closeout pass: dead code, refactor, code review, cleanup,
security re-scan, downstream check. Recorded as a delta vs the
[v1.4.0 delta](2026-10-12-v140-delta.md), per the audit cadence.

**Result: 6 findings — 1 MEDIUM, 2 LOW, 3 INFO. Five fixed in-cut; H-06 is
recorded, not fixed: it is a stdout behaviour choice with an owner to find.
Zero HIGH+ open. Every guard previously recorded as unproven is now proven by
a gate** (five of them), and no new one is recorded. The closeout's
independent code review found H-05, H-06 and two errors in H-01's first cut,
all before release.

## Findings

### H-01 — animation smeared in a terminal too small for the block · MEDIUM

Re-anchoring climbed one row per LF. That is the number of rows on screen only
when every line fits the terminal's width and the block fits its height.
`script(1)` cannot show the effect, because it transcribes bytes and does not
emulate a terminal. So the sweep built `scripts/term-model.py`, a model of the
few operations animation emits: deferred autowrap, cursor-up clamped at the top
row, scrolling at the bottom. It played v1.4.3's output through it:

| Input | 24×80 | 10×80 | 24×40 |
|---|---|---|---|
| 3 short lines (control) | 0 extra | 0 | 0 |
| 40-line block | **+17 rows / frame** | +31 | +17 |
| 5 lines × 162 columns | **+8.7 / frame** | +10 | +20 |
| 4 lines of CJK × ~110 columns | +1.5 / frame | +3.8 | +6.2 |

Each frame scrolled a copy of the block into scrollback, at ~60 frames a second
for the length of the animation. The wide-line case needs nothing unusual: any
line wider than the terminal, with a block that fits vertically. MEDIUM because
it is the feature's main path and it floods the user's scrollback. LOW would
fit a cosmetic glitch; nothing is lost or corrupted.

**Fix** (the user chose the full fix; [ADR 0005](../adr/0005-practical-subset-display-width.md)):
- when stdout is a terminal of known size, climb **physical rows**, counted
  with a display-width table generated from UAX #11 (`anuenue_cp_cols`,
  `_block_rows`);
- a block that still cannot fit is drawn once, with a `warn` record;
- an unknown size (a pipe, a pty answering 0 × 0, agnos) falls back to the LF
  count, so non-terminal output is byte-identical to v1.4.3 (18 animation
  streams compared).

**The fix's first cut had two errors**, both caught by the code review
before release:
- a hand-written 17-range width table. It called the BMP emoji UAX #11
  marks W 1 column wide: 76 columns then ✅✨⚡⭐ scrolled 100 rows over
  40 frames;
- a model of input escape sequences as zero-width. anuenue never delivers
  them intact (H-06), and an unterminated OSC swallowed every LF after it,
  undercounting below v1.4.3's own LF count.

The table is now generated (`scripts/gen-wide-table.py`, Unicode 16.0, 82
ranges), and an input ESC takes no columns while the bytes after it do.

**Gates**:
- `scripts/pty-check.sh` gate 5 checks the width table first:
  `anuenue_cp_cols` must equal Python's UAX #11 data at every
  cluster-starting codepoint to U+3FFFF. Dropping a single range fails it.
- the same gate then sizes a real pty with `stty`, records ten cases
  (including the review's three escape-bearing inputs and its MOTD-emoji
  line), and plays each into the model. Correct means no scrolling after the
  first frame, and several frames exactly when the block fits. v1.4.3 fails
  5 of the original 6.
- unit groups `v1.4.4 H-01` (+40 assertions).
- mutation-checked: every codepoint as width 1, escapes as width 1, and no
  draw-once fallback each fail the gate.

### H-02 — waiting on a non-blocking descriptor was polling, not blocking · LOW

The roadmap's surface 2 asked whether a stdin that never closes "degrades the way
the design says (blocked, not spinning)". Measured by a probe that writes one line
and then stalls, for 4 s:

| stdin | filter | MONO | animation slurp |
|---|---|---|---|
| blocking | 0 ms CPU | 0 ms | 0 ms |
| non-blocking | **30 ms** | **30 ms** | **30 ms** |

On a blocking descriptor, all is as designed:
- the line before the stall is rendered at once (animation, by design, waits
  for EOF);
- SIGTERM exits in 0.2 ms.

On a non-blocking one, the EAGAIN retry from F-01 (v1.3.5) slept 1 ms and
retried. That is about 1 000 wakeups a second, for as long as the stall
lasts. The write side's EAGAIN did the same with a stalled reader. LOW: the cost
is small, but it is the opposite of what both functions' comments promised.

**Fix**: `anuenue_wait_fd` blocks in `poll(2)` on the descriptor via the
stdlib's `fd_wait_ready`. That is the same syscall `sleep_ms` already issues, so
the surface does not grow. It falls back to the 1 ms sleep where the wait itself
fails (agnos: ENOSYS). After the fix: 0 ms in every case.

**Gate**: `robustness-check.sh` gate 6 gains four checks, three stdin routes and
one stdout case: a 2 MB stream into a stalled non-blocking stdout must cost
≤ 5 ms of CPU, then deliver every byte. v1.4.3 fails all four (20 ms each).

### H-03 — the documented capability surface named a syscall no route issues · INFO

ADR 0001's table, the integration guide and five source comments described the
heap as `brk(12)`. The sweep measured every route's syscalls under gdb.

**No route issues `brk`.** The stdlib allocator has used anonymous `mmap`
chunks since cyrius 6.1.19. The table also omitted animation's `fcntl`, `poll`
and `clock_gettime`. Measured, x86_64:

| Route | Syscalls |
|---|---|
| filter / MONO / one-shot | read, write, open + close (`/proc/self/cmdline`), mmap, exit |
| + colour auto-detection | `/proc/self/environ` (open, read, close), ioctl (TIOCGWINSZ) |
| animation | + rt_sigprocmask, signalfd4, fcntl, poll, clock_gettime, ioctl |
| `-v` | + clock_gettime, nanosleep |

Nothing surprising was found; the documentation was wrong, not the binary. **Fix**:
- the table and every comment are corrected;
- the measurement is now a gate, `scripts/fault-check.sh` layer 3: each route's
  syscall set must stay inside its allowlist. A build that adds one `getpid`
  fails all seven routes.

### H-04 — the line-buffer proof's worst case was mis-added · INFO

[Architecture 001](../architecture/001-buffer-geometry.md) summed escape (≤ 24),
codepoint (≤ 4), reset (4) and LF (1) in one column and gave **"≤ 29 — fits in
32"**. The column sums to 33. More to the point, the LF path and the codepoint
path never share an iteration.

The bound that matters is the codepoint path plus the reserve flush's reset:
24 + 4 + 4 = **32 — exactly the reserve, zero slack** at the 24-byte escape
budget, 7 with the 17-byte escape anuenue emits. It held, but by 0 bytes, not 3.

The unit group that should have caught it still described the v0.3.0 reserve
(22) and an 18-byte escape, and asserted `RESERVE ≥ 22`. **Fix**: the table now
bounds each path separately, and the group asserts
`RESERVE ≥ (ENTRY_SIZE − 8) + 4 + 4`.

### H-05 — animation dropped an extender with nothing to extend · LOW

Found by the code review, and present since M4. `_pretag_clusters` folded an
extending codepoint (a combining mark, a ZWJ continuation) into the open
cluster. That loses bytes in two cases:
- **After an LF**: the open cluster was the LF's, and `_render_frame` writes
  only reset + LF for one. `printf 'a\n\xcc\x81b\n' | anuenue -a` rendered
  `a\nb\n`.
- **At the start of the input**: no cluster was open, so none was created and
  `ctab[0]` pointed past the bytes. `\xcc\x81ab\n` rendered `ab\n`.

The filter path keeps both; only animation lost them. That breaks the
byte-preservation contract. LOW because the input is unusual: a combining
mark with no base.

Why nothing caught it: the pretag fuzz harness checked ranges and
monotonicity, not coverage.

**Fix**: an extender opens a cluster of its own when none is open, or when the
open one is an LF. **Gates**:
- `fuzz/pretag-clusters.fcyr` asserts coverage: the first cluster starts at
  byte 0, and an LF cluster is the LF alone. It gains a token corpus of
  LF / combining / ZWJ / RI shapes. On v1.4.3's code: 584 failures.
- a unit group (+6).
- `robustness-check.sh` gains four animation byte-preservation checks.
  v1.4.3 fails all four.

### H-06 — escape sequences in the input do not survive · INFO (recorded, not fixed)

> **Resolved at v1.4.5** for colour codes (the user's decision, 2026-10-14):
> on the colour routes the input's SGR sequences are now stripped, because
> anuenue owns the colour there, and MONO keeps them byte for byte. Other
> escape sequences still behave as described below. A producer-side
> "no colour" marker is roadmap v1.5.0.

Found by the code review while checking H-01. The renderer writes a phase
escape before every cluster, and an input ESC is a cluster of its own. So the
terminal sees the input's ESC followed at once by anuenue's, which cancels it
(an ESC in any state restarts escape processing). The rest of the input
sequence prints as text: `ls --color=always | anuenue` shows `[01;34m`.

This is true on every route and in every release; it is not a v1.4.x
regression. The output still carries every input byte, which is what the
robustness gate's byte-preservation check asserts.

Recorded rather than fixed. Either fix changes stdout bytes for input that
renders today, and they are a policy choice: strip input SGR, as Ruby
lolcat does, or pass a whole input sequence through as one zero-width,
untinted cluster. It is a trigger-gated item in
[roadmap § v1.x](../development/roadmap.md#v1x--trigger-gated). H-01's row
count already models what the terminal does today.

## The unproven guards — all five now proven

| Guard | Recorded unproven at | Proven by | Result |
|---|---|---|---|
| D-01 `_frame_wait` zero tick | v1.3.2 | `tests/probes/tick-probe.cyr` (tick 0 and −5) | returns; deleting the guard → timeout |
| E-01 zero-byte write | v1.3.3 | gdb: length set to 0, so the kernel returns 0 | exit 1, "write to stdout failed"; retrying instead → caught |
| EINTR, read and write | v1.3.5 | gdb: the first `read` / `write` returns −4 | retried, output byte-identical, exit 0, on filter / MONO / slurp; dropping either retry → caught |
| NOMEM (cmdit_new OOM) | v1.4.1 | `allocfail-probe.cyr`, under a genuinely exhausted heap | a real 0 handle → exit 1 through `anuenue_fail`'s no-allocation fallback, reported on stderr |
| signalfd `fd_set_nonblocking` failing | v1.4.0 | gdb: the first `fcntl` returns −EINVAL | warns, falls back, frames byte-identical |

The gdb injector (`scripts/gdb-inject.py`) changes exactly one syscall of the
real binary — the first match — and lets the rest through:
- **zero**: the length set to 0, so the kernel itself returns 0;
- **EINTR / failure**: the call turned into `getpid` at entry, and its return
  value rewritten at exit.

`scripts/fault-check.sh` skips its gdb layers cleanly without gdb, without ptrace
permission, or off x86_64. CI installs gdb. The NOMEM routing moved from
`src/main.cyr` into `anuenue_parse_runtime_failure` (`src/observe.cyr`) so the
probe could drive it.

## Closeout

- **Refactor**: `tests/anuenue.tcyr`'s `main()` held every unit group since M1,
  about 140 locals. Growing it by one group at v1.4.3 crashed the suite
  (upstream, below). It is now sixteen functions, one per milestone or cut,
  and the suite's output is line-for-line identical before and after.
- **Dead code**: one function in `src/` is reached only from tests,
  `anuenue_log_parse_name`. It is kept: it is the oracle for the fuzz
  harness's `parse(name(p)) == p` round trip, and DCE drops it from the binary.
  Its comment claimed two callers that do not exist, and is corrected. That is
  the remaining floor.
- **Cleanup**:
  - the unit geometry group's v0.3.0 comments (H-04);
  - five stale "unproven" comments rewritten to point at their gates;
  - the `brk` claims (H-03);
  - lint's deferral heuristic flagged "deferred autowrap" twice — prose,
    reworded, not suppressed.
- **Test infrastructure**: `pty-check.sh` matched the animation process by the
  literal name `anuenue`. So its own documented `BIN=build/anuenue-dce` usage
  failed gate 4. It now uses `BIN`'s basename.
- **Security re-scan**: no `sys_system`, exec, fork, socket or `open` in
  `src/`. The only raw syscalls are `exit` and two stderr writes. Every argv
  byte echoed to the terminal goes through the v1.4.2 sanitizer. The syscall
  surface is measured and gated (H-03).
- **Downstream**: thoth vendors `dist/anuenue.cyr` (at 1.3.6) for `/theme
  rainbow`. Its code is byte-identical to 1.4.4's, header aside, so the arc
  changes nothing for it. `state.md` listed no consumers; it now lists thoth.
- **Examples**: all nine `docs/examples/*.sh` run clean against 1.4.4.

## Code review of the arc

An independent review of `git diff 1.4.0 -- src/`, the arc plus this cut, with
each candidate defect reproduced:
- **Found**: H-05, H-06 and H-01's two first-cut errors (above);
- **Filed upstream**: agnostik's unchecked allocation (below).

Checked and found correct:
- **The word copy (v1.4.3)**: all eight `_emit_phase_esc` call sites enter
  with `pos ≤ 32 736` or `pos = 0`, so the 24-byte footprint ends by
  32 760. The other writes at the top-of-iteration `pos` — read-error flush,
  LF, EOF tail, carry exit, frame tail — are at most 5 bytes. The zero-fill
  covers `[entry + 8, entry + 32)`.
- **`_block_rows`** on plain text, every case through a pty and the model:
  lines of exactly `cols` (LF-terminated and as a partial last line), CJK at
  the last column, flags, CRLF, CR mid-line, input ending in CR. A block of
  23 lines on 24 rows animates, and 24 lines draws once. The sentinel and
  `utf8_seq_len`'s end index stay in bounds, and the fit check's boundary is
  right.
- **`anuenue_wait_fd`**: no return value can spin either loop.
  - 1 (including HUP / ERR) leads the retried call to EOF, EPIPE or an errno.
  - POLLNVAL sleeps 1 ms, then the retry fails with EBADF.
  - EINTR retries; 0 cannot happen with an infinite timeout.
- **The argv echo (v1.4.2)**:
  - a 64-byte token prints whole; 65 prints 64 + `...`;
  - a multi-byte cut steps back to its lead byte;
  - `abuf[64]` cannot overflow.
- **Parse errors**: every code anuenue's flag set can produce exits 2 with
  usage. NOMEM, the only code with a 0 handle, returns 1 before
  `print_usage`, and ARGV returns 1.
